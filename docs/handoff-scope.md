# 전달본의 포함 범위와 변경

## 포함

화면·정적 자산, 로컬/클라우드 서버, Bedrock 어댑터, 전체 코치 Instruction,
요구사항 스키마, 워크숍 규칙, CloudFormation, 계정 운영 도구, 합성 데이터 기반 검사,
고객 설정 예시와 재구성 문서를 포함한다. 정확한 파일 목록은 `handoff-files.json`에 있다.
기존 폰트 파일의 배포 라이선스는 `public/assets/Pretendard-LICENSE.txt`에 보존했다.

## 제외

원본의 환경 설정, 개인 문서, AWS 자격 증명, 워크숍 계정/비밀번호, 실제 배포 출력,
대화·PRD·로그·스크린샷 등의 운영 자료, 설치 의존성, Git 이력, 도구별 개인 설정은
복사하지 않았다. 과거 운영 검증을 고객 환경의 검증 완료로 표현하지 않는다.

## 고객 재구성을 위한 변경

- 계정·리전·모델·프로필은 빈 예시 설정으로 교체했다.
- 기존 배포 주소를 제거하고, Cognito 등 생성 값의 구조만 빈 출력 예시로 제공한다.
- 화면과 API의 특정 모델 고정 표기를 설정 가능한 일반 표시로 바꿨다.
- Bedrock 활성화 시 필수 설정을 검사하고, 클라우드 인증 설정이 없으면 시작을 거절한다.
- 배포는 오프라인 계획이 기본이며, 실행 계정 확인과 기존 스택 갱신의 명시적 선택을 추가했다.
- Bedrock IAM 권한은 고객이 선택한 정확한 리소스 목록으로 받는다.
- 계정 운영은 고객 스택 출력을 사용하고, 종료 예약 이름에 스택별 구분을 추가했다.
- 원래 개발 환경의 전용 브라우저 자동화는 제외하고, 고객 브라우저에서 확인할 항목을 문서화했다.
- 전달 파일 허용 목록, 식별정보 패턴 검사, 빈 설정 검사와 ZIP 생성 도구를 추가했다.

## 유지

코치 Instruction, 공통 워크숍 규칙, PRD 생성과 출처 검증, JSON 스키마는
원문 바이트를 보존했다. 해당 다섯 파일의 SHA-256을 전달 목록에 기록했다.
화면의 입력·추천·수정·검토·다운로드, 인증과 대화 분리 경계도 유지한다.

인프라 템플릿의 AWS 관리형 CloudFront 정책 UUID는 공용 정책 식별자이며 고객 계정
식별자가 아니다. 이를 빈 문자열로 만들면 인프라 템플릿이 동작하지 않으므로 보존했다.
공식 AI-DLC 문서의 커밋과 공개 링크도 설계 근거로 보존한다.

## 재공유

고객의 설정이 채워진 뒤에는 폴더 전체를 압축하지 않는다. `package:handoff`가 선택한
소스만 별도 임시 폴더로 복사하여 검사하고 ZIP에 넣는다. 소스에 추가한 기밀까지
완벽히 판별하는 DLP 도구는 아니므로, 새로 추가한 고객 데이터는 별도로 검토한다.
