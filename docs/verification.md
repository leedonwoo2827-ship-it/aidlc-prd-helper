# 고객 전달본 검증

이 문서는 전달본 코드의 검증 범위를 설명한다. 원래 운영 계정의 검증 결과와
접속 정보를 복사하지 않았다. 고객 계정에서의 실제 호출·배포·브라우저 확인은 별도다.

## 이번 전달본에서 확인한 결과

2026-11-20, 고객 설정이 비어 있는 별도 임시 복사본에서 확인했다.

| 검사 | 결과 |
|---|---|
| 기존 프로젝트의 의존성을 참조하지 않는 `npm ci --ignore-scripts` | 성공 |
| JavaScript 모듈 구문 검사 | 통과 |
| 회귀·설정·계정 오대상 방지·기밀 패턴 검사 | 23개 통과 |
| 실제 로컬 서버의 초기 자산, 비활성 모델, 비공개 경로 | HTTP 11개 통과 |
| 실행 중인 서버의 수신 주소 | `127.0.0.1` 확인, 검사 후 종료 |
| Instruction 및 문서 규칙 핵심 파일 | 원본 5개 파일의 바이트·SHA-256 일치 |
| 전달 목록과 빈 설정·기밀/식별정보 패턴 | 50개 파일 검사 통과 |
| 인프라 템플릿 | YAML 구문 및 리소스 참조 정합성 확인 |

실제 Bedrock 호출, 고객 AWS 계정 리소스 생성, Cognito 로그인, 브라우저 렌더링·조작은
이번 전달본 검증에서 수행하지 않았다. 아래 절차로 고객 환경에서 이어서 확인한다.

## 오프라인 자동 검사

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run verify:handoff
```

검사 내용:

- JavaScript 전체 모듈의 구문.
- 합성 fixture를 통한 입력·단계·문서 출처·보류·공통 워크숍 규칙.
- 대화 접근 키, 동시 쓰기, revision, 요청 재전송, 실패 응답 미반영.
- 스트리밍 임시 표시와 완료 후 확정의 구분.
- 빈 설정의 Bedrock 비활성, 필수 설정 누락 시 중단, 고객 모델 선택의 실제 요청 반영.
- 클라우드 인증·저장소·HTTPS origin 미설정 시 시작 거절.
- 오프라인 배포 계획에서 AWS 호출 없음, 다른 계정에서 apply 중단.
- 전달 파일의 빈 예시 설정, 식별정보 패턴, 보존한 핵심 파일 해시.

기존 회귀 검사는 로컬 HTTP 서버와 합성 coach를 사용한다. 클라우드 Cognito/DynamoDB의
실제 동작이나 선택 모델의 응답 품질을 증명하지 않는다. 테스트의 가상 식별자는
실제 계정 정보가 아니다.

## 고객 환경에서 실행할 검사

`npm run probe:bedrock`과 `npm run test:live`는 유료 Bedrock 호출이다.
`scripts/verify-deployed.mjs PRIVATE_ACCOUNT_JSON --run-live`는 고객 계정에
임시 사용자를 만들고 유료 호출을 수행한다. 계정/모델 설정 후 별도로 실행한다.

배포 후 확인:

1. 비로그인 `/api/me`와 위조 토큰이 401로 거절되는지.
2. 같은 워크숍 계정의 서로 다른 로그인에서 다른 대화의 읽기·쓰기·검토·삭제가 거절되는지.
3. 추천은 입력만 채우고, 응답이 점진적으로 표시되며, 완료 전 PRD가 확정되지 않는지.
4. 7개 답변, 미정, Q 출처, 공통 제외 항목이 문서에 유지되는지.
5. Markdown 편집이 검토 상태를 해제하고, 재검토 후 `prd.md`가 내려받아지는지.
6. 종료 시각 이후 기존 JWT가 거절되고 Scheduler가 계정을 실제 삭제하는지.
7. CloudFront를 우회한 S3 객체와 Function URL 직접 요청이 거절되는지.
8. 고객이 사용하는 데스크톱·태블릿·모바일 브라우저에서 입력과 다운로드가 가능한지.

실제 요청량, 모델 품질, 사용자 환경과 정책에 따른 운영 검증은 고객별로 수행한다.
CloudFormation 템플릿의 실제 생성, 모델 API 호환성, AWS 할당량과 권한은 오프라인
검사만으로 확인할 수 없다.
